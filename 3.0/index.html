Dieses Dokument spezifiziert DCAT-AP AT 3.0, das österreichische Applikationsprofil für die Beschreibung von Datensätzen, Distributionen und Datendiensten in österreichischen Open-Data-Portalen. Es basiert auf DCAT-AP 3.0.1 (europäischer Standard) und dem zugrundeliegenden W3C DCAT 3-Vokabular.

Gegenüber der Vorgängerversion DCAT-AP AT 2.1 bringt diese Version folgende wesentliche Neuerungen: Unterstützung für hochwertige Datensätze (High Value Datasets, HVD) gemäß EU-Durchführungsverordnung 2023/138, die neue Klasse dcat:DatasetSeries für Datensatz-Reihen sowie die obligatorische Angabe eines Identifikators (dct:identifier) für Datensätze. Außerdem werden die SHACL-Shapes als maschinenlesbare Validierungsregeln mitgeliefert.

Dieses Dokument ist ein Entwurf in Vorbereitung. Es hat noch keinen normativen Status. Inhalte, Anforderungen und Eigenschaftstabellen können sich bis zur finalen Veröffentlichung noch ändern.

Rückmeldungen und Kommentare sind willkommen über den GitHub Issue Tracker. Die aktuelle stabile Version ist DCAT-AP AT 2.1.

Management-Zusammenfassung

DCAT-AP AT 3.0 aktualisiert das österreichische Metadatenprofil auf den Stand von DCAT-AP 3.0.1 und bringt damit Konformität mit dem aktuellen europäischen Standard. Die wichtigsten Änderungen im Überblick:

Hochwertige Datensätze (HVD)
Die neue Eigenschaft dcatap:hvdCategory ermöglicht die Kennzeichnung von Datensätzen als hochwertig gemäß EU-Durchführungsverordnung 2023/138. Für HVD gelten spezifische Anforderungen an Zugangsbedingungen und Lizenzen.
Datensatz-Reihen (DatasetSeries)
Die neue Klasse dcat:DatasetSeries erlaubt die Beschreibung von thematisch zusammengehörigen Datensätzen, die als Reihe veröffentlicht werden (z.B. jährliche Statistiken). Einzelne Datensätze können mit dcat:inSeries auf ihre Reihe verweisen.
Verpflichtender Identifikator
dct:identifier ist für Datensätze nun verpflichtend (war bisher empfohlen). Der Identifikator soll persistent und eindeutig sein.
Aktualisierte Kardinalitäten
Für Distributionen sind dct:format und dct:license auf Anforderung der österreichischen Fachgruppe weiterhin verpflichtend.
SHACL-Shapes
Maschinenlesbare Validierungsregeln als SHACL Turtle-Datei sind nun Teil der Spezifikation: dcat-ap-3-at.hub.shapes.ttl.

Einführung

DCAT-AP AT ist das österreichische Profil des europäischen Metadatenstandards DCAT-AP. Es legt fest, welche Eigenschaften für die Beschreibung von Datensätzen und Datendiensten in österreichischen Open-Data-Portalen – allen voran data.gv.at – verpflichtend, empfohlen oder optional sind.

Standardhierarchie

DCAT-AP AT 3.0 ist in folgende Standardhierarchie eingebettet:

  1. W3C DCAT 3 ([[DCAT]]) – Basisvokabular des W3C für Datenkataloge
  2. DCAT-AP 3.0.1 ([[DCAT-AP]]) – Europäisches Applikationsprofil (SEMIC / Europäische Kommission)
  3. DCAT-AP AT 3.0 (dieses Dokument) – Österreichisches nationales Profil

Wichtigste Neuerungen gegenüber Version 2.1

ThemaÄnderung
Basis DCAT-AP 2.x → DCAT-AP 3.0.1; W3C DCAT 3
HVD Neue Eigenschaft dcatap:hvdCategory für hochwertige Datensätze gemäß [[HVD-IR]]
DatasetSeries Neue Klasse dcat:DatasetSeries; neue Eigenschaft dcat:inSeries

SHACL Maschinenlesbare Validierungsregeln als SHACL TTL
Profil-Konfiguration Piveau-Profil-Konfiguration als piveau.json mitgeliefert

Verpflichtungsgrade

Jede Eigenschaft hat einen der folgenden Verpflichtungsgrade:

  • verpflichtend — Muss angegeben werden (sh:minCount 1)
  • empfohlen — Soll angegeben werden, wenn vorhanden
  • optional — Kann angegeben werden

Klassen und Eigenschaften

DCAT-AP AT 3.0 definiert Eigenschaftsprofile für die folgenden Klassen. Die Eigenschaftstabellen sind aus den SHACL-Shapes (dcat-ap-3-at.hub.shapes.ttl) abgeleitet. Als neu gegenüber DCAT-AP AT 2.1 gekennzeichnete Eigenschaften sind mit NEU markiert.

Ein Datensatz (dcat:Dataset) ist eine identifizierbare Sammlung von Daten, die von einer Organisation veröffentlicht oder kuratiert wird. Er ist die zentrale Klasse in DCAT-AP AT. Hochwertige Datensätze (HVD)

Die EU-Durchführungsverordnung 2023/138 ([[HVD-IR]]) definiert sechs Kategorien hochwertiger Datensätze (High Value Datasets, HVD), die von öffentlichen Stellen kostenlos, maschinenlesbar und als API bereitgestellt werden müssen:

  1. Geodaten
  2. Erdbeobachtung und Umwelt
  3. Meteorologie
  4. Statistik
  5. Unternehmen und Eigentümerschaft
  6. Mobilität

Metadatenanforderungen für HVD

Datensätze und Datendienste, die hochwertige Datensätze gemäß [[HVD-IR]] bereitstellen, müssen folgende Eigenschaften angeben:

  • dcatap:hvdCategory mit einer URI aus dem HVD Category-Vokabular
  • dcatap:applicableLegislation mit dem URI des HVD-IR: http://data.europa.eu/eli/reg_impl/2023/138/oj
  • Für Distributionen: dct:license muss auf eine Lizenz zeigen, die der CC BY 4.0-Bedingung entspricht (z.B. http://creativecommons.org/licenses/by/4.0/)

Beispiel: HVD-Datensatz (Turtle)

<https://data.gv.at/katalog/dataset/my-hvd-geodata> a dcat:Dataset ;
    dct:title "Österreichisches Höhenmodell DHM"@de ;
    dct:description "Digitales Höhenmodell Österreich, 1m Auflösung."@de ;
    dct:identifier "dhm-at-1m" ;
    dcat:keyword "Höhenmodell"@de, "DGM"@de, "Geodaten"@de ;
    dct:publisher <https://data.gv.at/org/bev> ;
    dcat:contactPoint [ a vcard:Organization ;
        vcard:fn "BEV Kontakt" ;
        vcard:hasEmail <mailto:open-data@bev.gv.at> ] ;
    dcat:theme <http://publications.europa.eu/resource/authority/data-theme/REGI> ;
    dcatap:hvdCategory <http://data.europa.eu/bna/c_ac64a52d> ;
    dcatap:applicableLegislation <http://data.europa.eu/eli/reg_impl/2023/138/oj> ;
    dcat:distribution <https://data.gv.at/katalog/dataset/my-hvd-geodata/csv> .

Österreichische Vokabulare

Ergänzend zu den EU-weiten kontrollierten Vokabularen werden österreichspezifische Vokabulare unter dcat-ap.at/voc/ veröffentlicht. Diese Vokabulare sind als SKOS/RDF verfügbar und können in Metadaten referenziert werden.

Die österreichischen Vokabulare befinden sich in Vorbereitung. Die Vokabular-Seite unter dcat-ap.at/voc/ listet geplante und verfügbare Vokabulare.

Maschinenlesbare Artefakte

Zu dieser Spezifikation werden folgende maschinenlesbare Artefakte mitgeliefert:

dcat-ap-3-at.hub.shapes.ttl
SHACL-Shapes (Turtle) für die Validierung von DCAT-AP AT 3.0 Metadaten. Basiert auf den offiziellen DCAT-AP 3.0.1 SHACL-Shapes, erweitert um österreichspezifische Anforderungen (verpflichtende Felder für Distribution, Piveau-Mapping-Annotationen).
piveau.json
Piveau-Profil-Konfigurationsdatei für das österreichische Metadaten-Harvesting-System. Definiert die Zuordnung von SHACL-Shapes zu Klassen (core: Katalog und Datensatz; resources: Datensatz-Reihe, Datendienst, Katalog-Eintrag, qualifizierte Beziehung).
